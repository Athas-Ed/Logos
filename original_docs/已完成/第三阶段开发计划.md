## 1. 阶段目标（一句话）

在 **HTTP + SSE 契约稳定**的前提下，把产品从「能跑」推进为 **「Electron 桌面壳可靠托管 Python 后端 + Web GUI，日常可长期开着用」**；并行完成 **A7**、**MCP 子进程治理加固**、**契约工程小幅升级（可选）**。为后续 **A6 等 P2 能力** 仅保留架构与文档层面的扩展点，不在本阶段交付。

## 2. 主线 P0 — 高可用 Electron 壳层 + GUI 工程化

**含义**：「高可用」指**单机桌面场景下的进程与连接韧性**（非多机集群 HA）。设计细则与 Cursor 协作约定见 **`重要子系统开发文档/GUI开发文档.md`**。

| 主题 | 实施内容 | 理由 |
|------|----------|------|
| **后端生命周期** | Main 进程托管 `run_backend_stub`（或等价入口）：启动前健康检查、崩溃后有限次重启、退出时优雅关停子进程 | 避免「壳在、后端僵死」；与 `DECISIONS.md` §10 一致 |
| **基址与配置** | 打包态/开发态统一的 API base（环境变量 + 文档）；与 `bootstrap`、Vite `proxy`（`VITE_DEV_API_PROXY_TARGET`）一致 | 减少环境切换返工 |
| **SSE / 会话韧性** | 断线可感知、可重连或明确错误态；后端重启后的最小恢复策略 | 对话类产品核心体验 |
| **安全默认** | `contextIsolation`、受限 `preload`、不信任远程内容；生产 DevTools 门控 | Electron 默认攻击面控制 |
| **可观测** | 壳层日志与后端日志路径文档化；可选本地崩溃/重启计数 | 与 `obs.log_profile` 互补 |
| **打包与安装** | `electron-builder`（或等价）最小闭环：Windows 安装包或便携目录其一；代码签名后置 | 日常可用交付形态 |
| **自动化** | 至少一条 E2E（如 Playwright）：起壳 → 等后端 healthy → `bootstrap` 或最短 chat | 壳层回归可重复 |

**验收（P0）**：用户可据文档完成启动；上述 E2E 可本地或 CI 重复执行；无已知后端子进程泄漏。

### 7.2 P0 — 分步清单（步 1～11）

| 步 | 目标 | 主要产出 / 改动面 | 依赖 | 验收（本步完成即勾） |
|----|------|-------------------|------|----------------------|
| **1** | **`src/electron/` 可运行空壳** | 新建 `package.json`（electron、typescript、构建脚本）、`tsconfig` 区分 main/preload、最小 `main` 创建 `BrowserWindow`、占位 `preload`（可先空）；根或 `scripts/` 增加 `npm run electron:dev` 类入口 | 无 | 在已安装依赖的机器上，**仅执行壳命令**即可出现空窗体；README 或 `GUI开发文档` 补一句启动方式 |
| **2** | **开发态加载现有 GUI** | `loadURL(http://127.0.0.1:5173)`（或从 env 读端口）；文档写明：**默认**「先 `npm run dev`（gui）再启 Electron」；可选：检测 5173 未监听时给出 Main 内对话框或 stderr 提示 | 步 1 | 先起 Vite 再起壳，**可见现有 React 界面**；控制台无未处理异常 |
| **3** | **Main 启动 Python 后端子进程** | 解析 `python` / `uv run` / 仓库根路径（与 `run_backend_stub` 一致）；设置 `cwd`、`LOGOS_REPO_ROOT`、端口相关 env；日志把子进程 stdout/stderr 接到文件或 Main 可开关的 console | 步 1（可与步 2 同一 PR，若 diff 过大则拆） | 仅开 Electron（按文档「一键」或两步）时，**进程列表中出现后端**；`curl`/浏览器能访问 `health` |
| **4** | **健康门与就绪 gating** | Main 内轮询 `GET /api/v1/health`（或等价），超时阈值可配置；就绪后再 `loadURL` 或向 Renderer 发 `backend-ready`；未就绪时窗体显示加载态（可用简单 HTML 或 BrowserWindow 内嵌页） | 步 3 | 后端故意延迟启动时 **不长期白屏**；就绪后 GUI 可拉到 `bootstrap` |
| **5** | **退出与清理** | `before-quit` / `will-quit` / `window-all-closed`（按平台策略选型）中 **terminate 子进程**；Windows 注意进程树（必要时 `taskkill /T` 或专用库）；防止重复 kill 抛错 | 步 3 | 关窗或退出应用后，**无残留 Python 监听端口**；连续开闭 5 次无端口占用堆积 |
| **6** | **后端崩溃：有限次自动重启** | 监听子进程 `exit` 非 0；退避（如 1s/2s/4s）；最大重试次数；通过 IPC 通知 Renderer「后端恢复中/已失败」；可选写入用户目录计数日志 | 步 4～5 | 手动 kill Python 后，在次数内 **自动恢复**且 GUI 可继续请求；超过次数后 **明确错误态** |
| **7** | **单实例** | `app.requestSingleInstanceLock`；第二实例激活已有窗口并退出当前；与后端端口独占策略一致 | 步 1 | 双开安装快捷方式时 **不启动第二套后端**（或按设计将第二实例转发到第一实例） |
| **8** | **安全默认与 preload 白名单** | `contextIsolation: true`、`nodeIntegration: false`；preload 仅 `exposeInMainWorld` 必要 API（如 `getApiBase`、`onBackendStatus`）；生产禁用或门控 DevTools | 步 2 | 对照 **`GUI开发文档.md`** §2.3、§3 自检表打勾；无 `remote`、无 renderer 直接 `child_process` |
| **9** | **Renderer：基址统一 + SSE 韧性** | `src/gui`：集中 `apiBase`（env / `window` 注入二选一定案）；`EventSource` 或 fetch 流：**onerror 重连策略**、最大重试、用户可见提示；避免组件内硬编码 `127.0.0.1:8000` | 步 2；与步 4～6 的 IPC 约定对齐 | 断网或杀后端后 UI **不静默卡死**；恢复后能重新发起会话（以当前产品为准：新会话或续接文档化） |
| **10** | **生产构建路径** | Vite `build` 输出目录与 Electron `loadFile` / `loadURL` 方案定案；`electron-builder`（或等价）产出 Windows **便携或安装包其一**；`extraResources` 或脚本携带 Python 若本阶段不做，则文档要求本机已装 Python | 步 8～9 | 在未安装开发依赖的「干净」机（或 CI 工件）上，按 README **可启动完整 UI**；若仍依赖本机 Python，文档必须写清 |
| **11** | **自动化 E2E + 文档** | Playwright（或等价）：启动链按 README；断言 `health` 或 `bootstrap`；可选最小 `chat` 流；CI 或 `npm run test:e2e` 文档化 | 步 4 或步 10（可先对开发端口跑） | CI 或本地一键命令 **绿**；`README` / `ARCHITECTURE` 含「启动拓扑」小节 |

**步 3～5 注意**：与 **`scripts/run_backend_stub.py`** 行为对齐（入口、环境变量、端口），避免维护两套互斥逻辑；若抽公共「启动模块」，在 PR 说明中写明。

**步 9 注意**：若修改 SSE 事件消费或 REST 路径，必须走 **契约同步**（`.cursor/rules/logos-api-contract.mdc`）。
