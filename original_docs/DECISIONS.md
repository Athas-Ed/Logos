## 2. 仓库布局（已定案）

- **`src/`**：可导入包 **`logos`**（`src/logos/`：agent、infrastructure、persistence、tools、harness、**ports**）+ **`src/gui/`**（Vite + React + TS）。物理路径见 `src/README.md`。
- **`skills/`**：与 `src` 并列；MCP Skill 包、注册元数据、渐进式披露。
- **`config/`**：`defaults.yaml` + **`local.example.yaml`**；本机覆盖 **`config/local.yaml`（不入库）**。
- **`resources/`**：约定资源（可提交）。含 **`resources/prompts/`**（CB）、**`resources/entity_template/`**（实体形态契约）、**`resources/ksfs/`**（默认 **`paths.ksfs_root`**，树内用户内容常 **`.gitignore`**）。根目录可保留 **`resources/.gitkeep`**。
- **`example_ksfs/`**：示例 KSFS 树（可提交）。
- **`workspace/`**：工作空间（草稿、工件、**待落户设定**等；**非** KSFS 事实源）。默认忽略内容，**例外**：可提交 **`workspace/README.md`** 与 **`workspace/setting_entry/README.md`** 说明目录用途（见 `.gitignore`）。
- **`scripts/`**：一键启动脚本（**应提交**）。
- **`.index/`**：向量索引与 HSI 等运行时数据（**不入库**）。
- **`logs/`**：Obs 日志根（**不入库**）。
- **`models/`**：说明可提交；tooling 权重目录常忽略。
- **`original_docs/`**：内部文档。
- **`docs/`**：对外精修版（可选与 `original_docs` 同步）。

## 13. GUI 信息架构与会话管理（讨论定案，2026-05-16）

> **实现权威**：路由、目录、Electron 边界仍以 **`重要子系统开发文档/GUI开发文档.md`** 为准；**任务/Skill 产品主轴**以 **`重要子系统开发文档/任务与Skill驱动GUI定案.md`** 与 **§14** 为准。本节记录**工程定案**（档 B、标签、SSE、缓存页），供阶段计划与 Cursor 会话引用。

### 13.1 已定案（可开工依据）

| 主题 | 定案 |
|------|------|
| **应用路由** | **必须**引入 Router：`/chat/:id`（对话工作区）、`/settings`（设置独立页，自 `SettingsDrawer` 迁出）。 |
| **多任务 / 多对话** | 单 Electron 进程、单 `BrowserWindow`；**同一时间工作区只显示一个任务（会话）**；任务间用 **浏览器式标签条**跳转。对外文档优先称 **「任务」**；实现文件名可仍用 `conversation`。 |
| **切换时会话内 SSE** | **允许后台继续**（切走标签不强制 abort；须 UI 角标/完成通知等，实现期细化）。 |
| **跨重启** | **要保留**；归属 **档 B 本地会话缓存**（见 §13.4），**不是** KSFS 落户。 |
| **会话生命周期档位** | **档 B**：`draft → active → idle → archived → disposed`；**内存上限 + 懒加载**；非 `active` 会话内容**优先落盘**，不必常驻堆内存。 |
| **KSFS / 长期持久化** | **持久化轨**：由专用 **Skill**（用户另行开发）实现完整落户/联动；前端管理器 **不** 内嵌 KSFS 语义，**仅在用户明确指令**时调用该 Skill（或其后端入口）。 |
| **后台 SSE 并发** | 配置键 **`SSE_maxNum`**（落点见 §13.6）；**默认 3**；超额 **排队**（不拒绝）。 |
| **落盘格式** | **每会话一个 JSON**；文件内 **`schema_version`**（首版 **`1`**，见 §13.6 说明）。 |
| **标签条** | **顶栏**（工作区下方或窗口内容区顶部；与 Electron 系统标题栏分区实现）。 |
| **第一版 Router PR** | **同时**引入 Router、**`/settings`**，并预留 **`/cache`**（缓存管理，见 §13.8）；设置自 `SettingsDrawer` 迁出。**第五阶段**：默认首页改为 **技能面板 `/`**；`/chat/:id` 过渡为任务页或 `chat_inspire`（§14）。 |
| **缓存管理页** | **独立路由** `/cache`（§13.8）；入口 **仅** 设置页按钮 **「已归档会话」**，**不在顶栏**。 |
| **`disposed`** | **直接删除** JSON；**无**回收站（已定案）。 |
| **窄窗口** | 支持约 **1/4 屏** 日常使用；紧凑布局断点、输入区与次要控件收入菜单（见 GUI 开发文档 §6 迭代与 Playwright 窄 viewport 验收）。 |

### 13.3 会话切换 UI：三种侧栏模式 vs 已定标签页式

以下为讨论时列举的 **侧栏占屏策略**（用于对照，**非**最终交互定案）：

| 模式 | 含义 | 与本次定案关系 |
|------|------|----------------|
| **常显侧栏** | 会话列表固定占一列宽度 | **未选为默认定案**；窄窗下与「单工作区」冲突大 |
| **可折叠侧栏** | 列表可收起，展开时占宽 | 可作为**补充**（例如设置入口、文件夹树），**非**主切换方式 |
| **小窗默认隐藏侧栏** | 窄屏先藏列表，汉堡拉出 | 与标签页式可并存（标签为主、侧栏可选） |

**已定案**：主切换方式为 **标签页式** — 类似浏览器标签：**同一时刻仅一个对话占满工作区**，靠 **顶栏标签条**（小 footprint）在会话间跳转；与 §10「侧边栏式」并存时，**侧栏不强制常显**，避免 1/4 屏下双栏抢空间。

### 13.4 档 B 会话缓存（已定案）

- **原则**：`idle` / `archived` 会话的 **消息体、推理块、引用等大对象** 可从堆中卸下；标签栏与内存中保留 **元数据**（`id`、标题、更新时间、进行中流、未读角标等）。
- **落盘**：Electron **`userData`** 下专用子目录（如 `conversations/<id>.json`），**每会话一个 JSON**；跨重启恢复 **仅读此档 B 缓存**，与 KSFS 无关。
- **用户可见性**：使用者 **无需关心** 磁盘路径；**不** 在仓库浅层暴露 JSON。**唯一** 面向用户的缓存治理入口为 **`/cache` 缓存管理页**（见 §13.8）：展示 **摘要与占用**，**不** 默认暴露「打开文件夹」；开发者/Debug 打开目录若需要，仅开发者档位或环境变量。
- **路径治理**：由 **Main 窄 IPC**（如 `getConversationCacheDir()`）提供根路径；Renderer **禁止** 自选任意系统路径（见 GUI 开发文档 §3）。
- **S&G 关系**：若经 **`logos.tools` 文件原语** 读写缓存，须 **沙箱白名单**；生命周期策略 **不在 S&G**（见 §13.5）。

### 13.7 `archived` 与 `disposed`（语义定案）

| 状态 | 含义 | 标签栏 | 磁盘 JSON | 典型操作 |
|------|------|--------|-----------|----------|
| **`archived`** | **冷藏**：暂不常用，但可能再打开 | **不在顶栏标签显示**；在 **`/cache`** 列表中管理 | **保留** `<id>.json` | 用户「归档」；在缓存管理页 **恢复** 为 `idle` 并回到标签栏 |
| **`disposed`** | **销毁**：从工作集移除 | **移除** | **直接删除** JSON（**无**回收站） | 在标签或 **`/cache`** 批量勾选后 **一键销毁** |

- **`archived`** ≈ 浏览器里「从标签栏关掉但历史里还能找」或「收进归档夹」— **数据还在档 B**。
- **`disposed`** ≈ 「清空这条会话的本地缓存」— **档 B 结束**；若需进 KSFS，须走 **持久化轨 / 专用 Skill**，与 `disposed` **解耦**。
- **与 Obs**：会话缓存路径 **不必** 默认写入界面；Obs 日志仍按 `logs/` 规范，**不** 将会话 JSON 目录当作用户日志根展示（除非 `obs.show_log_root_in_gui` 类开关扩展到调试项，非默认）。

### 13.5 对话生命周期管理器：放哪一层、与 CB / S&G 如何配合（已定案）

```text
┌─────────────────────────────────────────────────────────────┐
│  Renderer（src/gui）                                         │
│  · ConversationLifecycle（档 B）：多会话、标签、路由、        │
│    多路 SSE 订阅、内存上限、懒加载/落盘、跨重启恢复           │
│  · 组装 POST /api/v1/chat 的 messages[]                    │
└───────────────────────────┬─────────────────────────────────┘
                            │ HTTP/SSE（无会话 id 的现行契约）
┌───────────────────────────▼─────────────────────────────────┐
│  I&I（ii_layer）                                              │
│  · 无状态 chat；每请求独立                                    │
│  · 未来若增加「会话 CRUD / 搜索」REST → 属持久化轨，非 GUI  │
│    管理器内部逻辑                                             │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  Shell + CB（agent）                                          │
│  · CB：单次请求内模板、历史裁剪、上下文预算（消费 messages[]） │
│  · 不知 GUI 标签 id；不持有多会话 UI 状态                     │
└───────────────────────────┬─────────────────────────────────┘
                            │ 工具调用（按需）
┌───────────────────────────▼─────────────────────────────────┐
│  S&G + tools                                                  │
│  · 路径沙箱、白名单、输出过滤、MCP 治理                       │
│  · 持久化轨：读 KSFS、检索、晋升草稿等由工具/端口执行         │
└─────────────────────────────────────────────────────────────┘
```

| 组件 | 是否负责「多会话生命周期」 | 说明 |
|------|---------------------------|------|
| **前端 ConversationLifecycle** | **是（档 B 归属）** | UI 状态机、标签、缓存落盘、多路 SSE；**目标态**每次执行携带 **`skill_id`** 与任务输入，而非无标识全工具 `chat`。 |
| **S&G** | **否** | 仅治理 **工具路径与输出**；不解析标签、不缓存对话。 |
| **CB** | **否（单次请求）** | 根据**当前请求**中的 `messages` 与 `operating_mode` 构建上下文；多会话合并/裁剪策略若需全局一致，将来可通过 **端口或显式 API 参数** 传入，而非 CB 直接读 GUI 缓存目录。 |
| **持久化轨（档 C）** | **后端 + Skill / 工具** | KSFS 落户、长期存档等；**用户显式指令** 时由前端触发专用 Skill；**不**纳入 ConversationLifecycle 核心。 |

### 13.8 缓存管理页 `/cache`（产品定案，2026-05-16）

与 `archived` / `disposed` 划分一致，是档 B 的**用户可见治理面**。

| 能力 | 定案 |
|------|------|
| **路由** | 独立页 **`/cache`**（窄窗友好）。 |
| **入口** | **仅** 自 **`/settings`**：**按钮文案「已归档会话」** → `navigate('/cache')`。**禁止**在顶栏标签区或顶栏主菜单增加 `/cache` 入口。 |
| **列表** | 仅 **`archived`** 会话：展示 **摘要**（标题、最后活动时间、约略条数/大小等，由 JSON 元数据或轻量扫描得出）。 |
| **恢复** | 选中后 **恢复到工作区** → 状态改 `idle`，**回到顶栏标签**。 |
| **销毁** | 勾选一条或多条 → **一键销毁**（`disposed`，**直接删**对应 JSON）。 |
| **占用展示** | 当前缓存 **总大小**（`userData/conversations/` 由 Main IPC 统计，Renderer 不拼路径）。 |
| **阈值配置** | 配置键 **`ui.cache_warn_bytes`**；**默认 `524288000`（500 MiB，即 500×1024×1024 字节）**；在 **`/settings`** 内可调（实现期可为数字输入或预设档位）。 |
| **启动提醒** | 当占用 **≥ `ui.cache_warn_bytes`** 时，**每次冷启动** Logos 可弹一次提醒，引导前往设置 →「已归档会话」→ `/cache` 清理。 |
| **提醒冷却** | 用户可选：**「稍后提醒」**（本次启动不再弹）、**「7 天内不再提醒」**（本地记录截止时间，存 `localStorage` 或等效，**不写** `config/local.yaml`）；冷却结束后恢复启动检测。 |
| **不暴露目录** | 页面上 **不** 展示绝对路径、**不** 提供「在资源管理器中打开」为默认项。 |
| **返回导航** | `/cache` 须提供返回 **`/settings`** 的入口（返回按钮或面包屑），避免窄窗下无法退出子页。 |

**实施顺序建议**（讨论）：首版 Router PR 可 **预留路由与占位页**；设置页含 **「已归档会话」** 跳转；完整列表/批量/阈值调节可与 **多标签 + 归档** 同一里程碑或紧随其后。

### 13.6 配置与 JSON 约定（已定 / 说明）

| 项 | 定案 |
|----|------|
| **`SSE_maxNum`** | 后台并发流式 `chat` 上限；**默认 `3`**；超额 **排队**。落点：`config/defaults.yaml` 的 **`ui.SSE_maxNum`**（或 `local.yaml` 覆盖）；GUI 可选只读展示，首版不必单独设置页字段。 |
| **`ui.cache_warn_bytes`** | 会话缓存占用 **告警阈值**（字节）；**默认 `524288000`（500 MiB）**；**`/settings` 可调**；经 `bootstrap` 或等价下发至 GUI（若实现期纳入 `GET /api/v1/bootstrap` 的 `ui` 段，须走契约轨）。 |
| **`schema_version`** | 每个会话 JSON 根部的 **整数版本号**（首版 **`1`**）。**用途**：升级应用后若 JSON 字段改名/增删，启动或读盘时根据版本 **迁移** 旧文件，避免静默读错。用户 **无需理解** 该字段；实现者维护迁移表即可。 |
| **契约轨** | 若持久化轨新增 `GET/POST /conversations` 等，走 **API-V0.2 + logos-api-contract** 单 PR 闭环。 |
| **会话保存 Skill** | 摘要见 **`重要子系统开发文档/会话保存Skill文档.md`**；**当前不实现**。 |

### 14.4 地基评估、风险与假设（2026-05-16）

> **用途**：供协作者判断「是否需要推倒重来」；**结论：不必推翻下层，须补齐上层与 Skill 竖切片**。

#### 评估摘要

| 层 | 牢固度（粗评） | 依据 |
|----|----------------|------|
| **下层**（工具、MCP、CB/Shell、KSFS、S&G、I&I、契约测） | **较高** | `pytest` 约 **110** 项通过；`test_stream5_api`、MCP 泄漏测、KSFS e2e；第四阶段 A7/MCP/Obs 已结案 |
| **上层**（任务 GUI、产品 Skill、`skill_id`） | **偏低** | G1～G4 有实现但默认路径曾为全工具 Chat；`skill_id` **文档已定、代码未接**；Playwright smoke 仅少量 |
| **业务 Skill**（语病、导入、启发等） | **低** | `skills/` 以 MCP 示例为主；设定导入仍封存规格 |

**架构方向**：DIP + 分层 + KSFS 事实源 + MCP 仅作工具供给 — **正确**；张力在于 **无状态 `chat` + 全工具 ReAct** 与 **任务/Skill 驱动** 尚未在默认路径闭合，属**产品债**，非结构债。

#### 工作假设（第五阶段默认成立）

1. **不推倒 `src/logos` 分层**；变更以 **组合根按 `skill_id` 裁 registry**、CB 模板键为主。  
2. **不废弃** Electron、档 B JSON、标签条、`ConversationProvider`；语义改为 **多任务槽**。  
3. **T1 优先 P2 单任务竖切片**（如 `lint_zh`），验证上层接口，而非继续加厚默认 Chat。  
4. **契约测不退化**：`test_stream5_api`、`test_sse_chat_contract`、MCP 相关测为合并门槛。  
5. **文档已定案项**（`任务与Skill驱动GUI定案.md`、`Skill形态与Prompt工程.md`）与 PR 冲突时，**先改代码或显式修订文档**，避免长期「文档一套、默认可执行路径另一套」。

#### 主要风险

| 风险 | 表现 | 缓解 |
|------|------|------|
| **默认全工具 Agent** | 用户绕过 Skill 仍获完整工具目录 | F5-08 前：`skill_id` 必填或开发环境外仅白名单；S&G 保持 |
| **GUI 状态机复杂** | 多标签 × SSE × 全局 store 曾引发请求风暴与卡顿 | 任务输入本地化；`done` 早结束 SSE；少在 Chat 堆功能 |
| **产品/工具 Skill 混称** | 每个 MCP 包被当成产品 Skill | 遵循 **`Skill形态与Prompt工程.md` §2** |
| **上层超前下层** | 面板与向导先于 scoped 执行 | F5-05 与 F5-02/`skill_id` 契约同里程碑或紧随其后 |
| **范围蔓延** | G5/M-UI/全功能 Chat 与 F5 轨抢资源 | G5/M-UI **冻结**至 F5-05 后（见 **`第五阶段开发计划.md`**） |

#### 非目标（本阶段勿误判为「地基不牢」）

- 要求 **OpenAPI 自动生成**、**安装包/签名**、**真壳 E2E 全覆盖** — 已顺延，不列入地基验收。  
- 要求 **设定导入全链** — 属 **A6 / P0 Skill**，依赖 A7 与封存规格恢复，非 GUI 多标签问题。  
- 因 Prompt 回显、SSE 边角 bug **否定 Electron 或多任务持久化** — 属上层运行时打磨，已针对性修复，架构仍保留。

#### 三条执行原则（PR 自检）

1. 该改动是否服务于 **「用户先选 Skill → 再执行」**？否 → 慎并入 F5 轨 PR。  
2. 是否削弱 **scoped 工具 / 契约测试**？是 → 须契约轨与单测同 PR。  
3. 是否在 **加厚万能 Chat**？是 → 改为 Skill 任务页或明确标 `developer-only`。

## 12. KSFS 摄入策略与能力层扩展（已定方向，2026-05-11）

**流水线与 HDL 细则以 `重要子系统开发文档/KSFS开发.md`（§3.0、§3.5、§7.3）为准**；本节为**全局摘要**。

### 12.1 策略要点

- **事实源**：KSFS **仅 `.md`** 进入 HDL 核心扫描；**.docx / PDF 等不进入核心解析管线**。
- **设定类 SSOT**：**落户**到 `ksfs_root` 且经 HSI 登记的实体为设定类叙事知识的**权威依据**；外部 Word 可为创作稿或归档；**默认不维护** Word 节级映射。
- **导入流水线**：**Skill + 粘贴 → LLM 结构化 JSON → JSON Schema 校验 → 本地渲染 → `workspace/setting_entry/` 草稿 → 人审 → 晋升 `ksfs_root`**；**持久 `id` 仅在落户后**由 HSI 分配。
- **草稿与建议**：**必有**可晋升草稿；若有值得修改处，**另附** `suggestions[]`；md 中可呈现独立章节（如 `## 修改建议`）；**禁止**「仅建议、无草稿」为导入常态。
- **双模板 / 单契约**：**提取规格**（LLM，与 schema 同源）+ **渲染规格**（本地）；**Prompt 黑白名单**为软约束；**硬闸门**为 schema + 本地渲染 + 沙箱。
- **重叠与分流**：与**已落户实体**重叠时，导入流**不静默覆盖**；转交未来 **「KSFS 修改」** 能力或显式用户选择。

### 12.2 未来可扩展（非当前核心）

- **`.docx` 摄取 Skill（可选）**：抽取或辅助粘贴；**非** HDL 核心。
- **「KSFS 修改」Skill**：已落户实体的受控改写 / 合并 / 提案；与导入**分规格、分入口**。
