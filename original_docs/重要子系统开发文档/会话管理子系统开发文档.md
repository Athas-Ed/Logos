## 1. 子系统边界

| 在范围内 | 不在范围内（本专项） |
|----------|-------------------|
| 顶栏 **标签**（`openTabIds`）与 **路由**（`/task/:id`、`/chat/:id`、`/lab/:id`）一致性 | 档 C：会话升格作品库 / KSFS |
| 内存态 **`ConversationProvider`** + **`useConversation`** | HTTP/SSE 契约（见 **`API-V0.2.md`**） |
| Electron **IPC** 读写 `conversations/*.json`（`idle` / `archived`） | G5 **启动占用提醒**（`cache_warn_bytes`，见 F6-05） |
| **归档 / 恢复 / 销毁** 与标签栏联动 | M-UI 纯 CSS 调校 |
| 多路 SSE 排队、`SSE_maxNum` 与标签元信息展示 | 后端会话存储 |

**产品语义（已定案）**：

- 一个 **任务 = 一个会话 JSON**；顶栏标签 = **进行中的任务槽位**。
- **归档** = 顶栏移除 + 磁盘 `status: archived`（仍可在 **`/cache`** 恢复或销毁）。
- 首页为 **技能面板** `/`；冷启动**不必**自动打开空白「默认聊天」标签。

## 2. 当前已实现（代码快照）

| 模块 | 路径 | 职责 |
|------|------|------|
| 全局 Store | `src/gui/src/conversation/ConversationProvider.tsx` | `byId` 内存、`openTabIds`、SSE 队列、`createTask` / `archiveTab` / `restoreArchivedConversation` |
| 订阅 | `subscribe.ts` + `useSyncExternalStore` | 按会话 id 细粒度刷新 |
| 防抖写盘 | `persistScheduler.ts` | `idle` 态 ~600ms 防抖写 JSON；`archived` 不写 |
| 记录拼装 | `record.ts` / `createEmptyConversation.ts` | `ConversationState` ↔ 磁盘 JSON |
| IPC | `conversation/ipc.ts` + Electron preload | `list` / `read` / `write` / `destroy` / `totalBytes` |
| 顶栏标签 | `components/TabBar.tsx` | 切换路由；× → **`archiveTab`** |
| 任务页归档 | `pages/TaskPage.tsx`、`AppShellToolbar.tsx` | 「归档任务」「归档当前会话」 |
| 缓存页 | `pages/CachePage.tsx` | 列表、恢复、销毁 |
| 路由工具 | `conversation/routeUtils.ts` | Hash 路径下判断是否在会话页 |

**启动加载（修订后）**：

- 仅将磁盘 **`status === "idle"`** 的会话 id 填入 `openTabIds`；**无 idle 时顶栏为空**，不注入 `default` 占位标签。

**归档写盘（修订后）**：

- 归档前 **`cancelConversationPersist`**，避免防抖把 `idle` 盖回归档；
- 归档过程 **`closingTabsRef`** 屏蔽 **`ensureOpenTab`** 把标签加回；
- 写盘 **`await writeConversationIpc`** 后再延迟释放屏蔽。

## 3. 架构关系（简图）

```text
技能面板 / 新建任务
        │
        ▼
 createTask / createInspireChat / openConversationTab
        │
        ├─► byId[id] 内存态 + navigate(/task|/chat|/lab/:id)
        │
        ▼
 TaskPage / ChatPage ──useConversation(id)──► ensureOpenTab(id)  [仅 idle 且非 closing]
        │
        ├─► patchConversation ──► scheduleConversationPersist (idle)
        │
        ▼
 archiveTab ──► cancelPersist + write archived + 从 openTabIds/byId 移除 + 必要时 navigate("/")
        │
        ▼
 /cache ──► restoreArchivedConversation ──► idle 写盘 + 顶栏加回 + navigate
```

## 4. 已知问题与根因（验收沉淀）

| 现象 | 典型根因 | 修订状态 |
|------|----------|----------|
| 点击归档后标签仍在 | 路由仍停在 `/task/:id`，`useConversation` → **`ensureOpenTab` 无条件把 id 加回 `openTabIds`** | ✅ `closingTabsRef` + 校验磁盘 `archived` |
| 关标签（×）有时无效 | 同上；× 实际调用 **`archiveTab`**，与页面 `ensureOpenTab` 竞态 | ✅ 同上 |
| 重启后已关/已归档标签又出现 | **`stopStream` → `patchConversation` 在 `cancelPersist` 之后又调度防抖写盘**，~600ms 用 `idle` 盖回 `archived`；启动曾信任列表 meta 且读失败仍建空标签 | ✅ `closingTabsRef` 抑制归档期写盘；**先 await 写 archived 再改顶栏**；启动二次校验 `read.status`；`sessionDismissed` 修复历史脏 `idle` |
| 连续归档/新建后输入框失效 | 归档后路由未离开 + **`ensureOpenTab` 用空记录 `patchConversation` 复活幽灵会话**；或 `streaming`/`queued` 未清 | ✅ 归档清队列/pending；无效路由回首页 |
| health 轮询过频 | 任务路由下每 60s `fetchHealth` | ✅ 改为 180s |

## 6. 讨论钩子（改进方向，非定案）

1. **标签 = 打开列表还是进行中全集？**  
   当前启动恢复**全部 idle 文件**；是否应改为「仅恢复上次未关标签」？与作家「多任务并行」习惯如何平衡？

2. **× 关闭与「归档任务」是否同一操作？**  
   现实现二者均 `archiveTab`。是否需要「仅关标签、仍 idle 写盘」以便下次从面板继续？

3. **`default` 会话是否退役？**  
   `ChatPage` 仍可将非法 id 重定向到 `default`；与「无 idle 不建标签」并存时，深链 `/chat/default` 行为需产品拍板。

4. **`ensureOpenTab` 是否仍需要？**  
   可否改为：仅 `create*` / `restore*` / 用户点标签时修改 `openTabIds`，页面 mount **不再** 副作用加标签？

5. **SSE 全局队列与 per-tab 状态**  
   归档时若未 `stopStream` / 未清 `activeStreamCount`，会导致新任务无法提交（输入框像「失效」）。是否在 Store 层做「会话生命周期」统一 teardown？

6. **Electron 与浏览器 dev 双轨**  
   无 IPC 时行为与 Electron 不一致；是否要在 dev 也提供 localStorage 模拟层以便早测会话逻辑？
