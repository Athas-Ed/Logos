# Logos — Harness Engineering（生成质量与编排）

> **地位**：约定 **`src/logos/harness/`** 与 **`src/logos/agent/`** 中与 **「模型输出是否好用」** 相关的工程边界：ReAct 编排、上下文拼装（CB）、范式路由（PR）、与 **Retrieval / MS** 的接线方式等。**不替代** **`API-V0.2.md`**（HTTP/SSE 形状）、**`SPEC-DISPLAY-AND-LOGGING-V0.1.md`**（展示档位与 `log_profile` 正交）、**`KSFS开发.md`**（事实源与 HDL）。  
> **与「性能」一词的关系**：在阶段计划与日常沟通中，**「性能」默认指软件自身性能**（UI、内存、管线延迟等），见 **`../已完成/第四阶段开发计划.md`** §8；**本文覆盖的是另一类工作**：**B — LLM 输出质量 / 检索相关性 / 提示与路由策略**，与第四阶段主线（A7 / MCP / Obs）**解耦**，按需**持续迭代**，不阻塞工具链里程碑。

## 2. 预期效果（长期，非单次阶段验收）

| 维度 | 预期 |
|------|------|
| **可复现** | 同一 `operating_mode` + 同一配置快照下，核心用例输出**可对照**（允许模型固有随机，但须记录 seed/参数策略）。 |
| **可诊断** | 「坏答案」能区分：**检索空 / 检索噪声** vs **模型未遵守指令** vs **工具失败**；与 **`Obs开发文档.md`** 中的工具链字段互补。 |
| **可演进** | Prompt / CB 片段 **版本化**（仓库内路径约定）；大改走评审或小范围 A/B，而不是隐式散落在代码字符串中。 |
| **与产品边界一致** | 不默认引入多租户、不外泄本机 `127.0.0.1` 信任边界外的能力。 |

## 3. 分步开发与验收（建议；不与第四阶段 §2 抢序）

以下可在 **`../已完成/第四阶段开发计划.md`** 主线稳定后并行，或由专人维护 **独立分支/里程碑**。

| 步 | 目标 | 验收（建议） |
|----|------|----------------|
| **H1** | **基线用例集**：作家/编剧各若干条，覆盖检索命中、无命中、多轮工具 | 文档或 `tests/` 中可运行脚本；人工或半自动打分表（可极简） |
| **H2** | **检索质量旋钮**：top-k、snippet 长度、重排开关与配置键文档化 | 改变键后行为可观察；与 HDL 只读约束无冲突 |
| **H3** | **CB 预算与裁剪**：历史轮次、工具结果进入上下文的截断规则可解释 | 超长对话不 OOM；关键系统消息不丢（以文档为准） |
| **H4** | **模型路由**：多供应商 / 多模型切换路径与失败降级 | 配置错误时 **fail fast** 或可观测错误消息（与 I&I 一致） |

## 4. 开发要点与建议

1. **改动若触及对外契约**（`api_v1`、`sseChat` 等），仍必须走 **`.cursor/rules/logos-api-contract.mdc`**；本文**不**授予绕过契约的权限。  
2. **展示与生成解耦**：「少显示推理全文」是 WM/SPEC 问题；「推理步骤是否对写作有用」是 Harness 与模型问题，勿混为一谈。  
3. **与 Obs 协同**：调参与实验结论尽量留下 **日志或 ADR 式记录**（`DEVLOG` / 本文修订表），便于与 Obs 调用链对照。  
4. **持续迭代预期**：本轨道**不设「一次 PR 彻底修好 RAG」**的验收；以回归集不恶化 + 关键 bug 修复为增量标准。
