> **起始锚点（2026-05-14）**：第三阶段 **P0** 已交付；原第三阶段 **P1** 中 **契约工程**、**Electron 深度产品化**、**真壳 E2E** 按本文 **顺延至下阶段**（指导性文件见 **`重要子系统开发文档/产品化文档.md`**）。

## 1. 阶段目标（一句话）

在 **P0 桌面壳已可用**的前提下，本阶段**先完成「草稿 → KSFS」晋升工具链（A7）**，同步完成 **MCP 子进程治理加固** 与 **Obs 调用链 / 落盘可观测性增强**（详见 **`Obs开发文档.md`**）；在以上主线**稳定合入后**，本阶段**后期**安排 **软件自身性能**（profiling 与小步优化，见 **§8**、**§9.3**）。**A6 设定导入**、**契约 OpenAPI/schema**、**安装包 / 签名 / 自动更新 / 真壳 E2E** 等**不纳入本阶段验收**，其中桌面产品化分步见 **`产品化文档.md`**。

---

## 2. 主线队列与冻结优先级（已定案）

以下顺序为**本阶段交付与合并的优先次序**（同一步内子任务仍以各小节表格为准）；**并行**时不得破坏该顺序所表达的**依赖意图**：**晋升（A7）先于设定导入（A6）**；Obs 与 MCP 在进程与日志字段上需**协同**（见 **`Obs开发文档.md`** §2 与 **`MCP开发.md`** §3）。**可直接打勾推进的线性清单与每步验收**见 **§9**。

| 优先级 | 项 | 说明 |
|:------:|----|------|
| **1** | **A7 草稿晋升 CLI**（`DraftPromotionPort`） | 本阶段**必须先完成**；与桌面工作区、KSFS 事实源衔接。 |
| **2** | **MCP 子进程治理加固** | 与 Electron **长生命周期**同频；泄漏、重复对话、配置边界。 |
| **3** | **Obs 与调试体验** | 本阶段**重要组成**；分步、验收与要点见 **`重要子系统开发文档/Obs开发文档.md`**。 |
| **4** | **软件自身性能**（默认「性能」语义，见 **§8**） | 本阶段**后期**执行：**不阻塞** 1～3 主线；以 profiling、热点消除、IO/内存与长会话前端表现为主要抓手；与 **`Obs开发文档.md`** 排障数据互补。 |

**顺延至下阶段（本阶段不验收）**

| 项 | 说明 |
|----|------|
| **契约工程**（OpenAPI / Pydantic → schema 等） | 原 P1-API；在 **`API终极文档.md`** §6 补一句「顺延至下阶段」即可，不在本阶段排期。 |
| **A6 设定导入全链** | 须在 **A7 晋升** 可用后再单独立项；依赖 **`设定导入Skill开发.md`** 与 KSFS 文档。 |
| **Electron 产品化大块** | 安装包、代码签名、`electron-updater`、托盘常驻、CI 发布矩阵、真壳 E2E 等；见 **`重要子系统开发文档/产品化文档.md`** 分步 A～F。 |

**验收（本阶段）**：A7 行为符合 **`KSFS开发.md`** 相关章节；MCP 集成测无僵尸进程、进程数稳定有证据；Obs 达到 **`Obs开发文档.md`** 中 **O1～O5** 已划入本阶段的验收行（O4 为可选则按该文标注）。**软件性能（§8、优先级 4）** 以「有 profiling 记录或 issue 闭环、无已知灾难性退化」为最低验收，具体指标由执行 PR 在说明中写明。

### 2.1 A7 — 草稿晋升 CLI（`DraftPromotionPort`）

| 步 | 目标 | 主要产出 | 依赖 | 验收 |

| **P1-A7-3** | **文档与可选 GUI 入口** | `README` / KSFS 文档互链；若设置页需「打开日志目录」等，**薄封装** CLI 或 shell API | P1-A7-2 | 与 **`GUI开发文档.md`** 无矛盾；**不**强制 GUI 首屏暴露 |

### 2.2 MCP — 子进程治理加固

| 步 | 目标 | 主要产出 | 依赖 | 验收 |

## 8. 「性能」语义与排期（已定案）

团队口头或文档中的 **「性能」**，**若无特别声明，默认指 A**。

| 代号 | 含义 | 本阶段排期 | 权威文档 |
|------|------|------------|----------|
| **A** | **软件自身性能**：UI 卡顿、内存、大 `workspace` 下列表渲染、检索 / Embedding **管线耗时**、磁盘 IO、Electron 与后端进程资源等 | **阶段后期**（优先级 **4**，在 A7 / MCP / Obs 主线稳定后）；**profiling + 小步优化**；与 **`Obs开发文档.md`** 排障数据互补 | 本文件 §2、§4 |
| **B** | **LLM 输出质量 / Harness 编排**：提示词、RAG 相关性、模型路由与参数、ReAct/CB 策略等 | **不纳入本阶段里程碑**；**持续迭代**，与工具链 PR **解耦** | **`重要子系统开发文档/Harness Engineering文档.md`** |

若某次讨论**明确**涉及 B，应直呼「生成质量 / Harness / RAG」等，避免与 **A** 混用「性能」一词。

**阶段后期软件性能**的逐步验收见 **§9.3**（S12～S15）。

## 9. 执行清单：逐步推进与验收

按 **S1 → S2 → …** 顺序推进；**同一编号内**可拆多个 PR，但**须满足该步验收**后再进入下一步。**S12～S15** 须在 **S1～S11** 均已满足后再立项。**G 轨**可与 **S4～S11** 并行，**不得早于 S3**（避免无 CLI 却先做大量 GUI 封装）。细则仍以 **§2.1～§2.2** 与 **`Obs开发文档.md`** 为准；本表为**可打勾的总序**。
