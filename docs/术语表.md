# 术语表（Glossary）

Logos 对外文档与架构说明的统一用语。实现细节、排期与定案草稿见本机 `original_docs/`（不入库）。

**与行业易混词**：见 [§9 行业对照](#9-行业对照)。

---

## 1. 系统与角色

| 术语 | 英文 / 代码 | 含义 |
|------|-------------|------|
| **Logos** | — | 面向游戏叙事的本地写作 Agent；支持作家 / 编剧等运行模式。 |
| **Agent** | `src/logos/agent/` | **Agent 决策层**：编排与上下文，含 Agent 调度器、CB、PR。 |
| **Agent 调度器** | Shell（`shell.py`） | 任务执行入口；经**端口**调用检索、模型等。对外请称 **Agent 调度器**，避免单独使用 Shell。 |
| **OM** | `operating_mode` | **运行模式**：`author` / `director` 等；**不**表示展示档位。 |
| **Pd** | `presentation` | **展示档位**：`work`（≈ WM）与 `developer`；与 OM、Obs **日志**正交；**不**决定是否在 GUI 暴露全文推理（见 §5.1）。 |

## 2. Agent 组件与执行范式

| 术语 | 英文 / 代码 | 含义 |
|------|-------------|------|
| **CB** | Context Builder | **上下文构建器**（context engineering）。 |
| **PR** | Paradigm Router | **范式路由器**；读取 manifest 的 `paradigm`。 |
| **执行范式** | `paradigm` | Agent **执行策略**（非 GoF 设计模式泛指）。 |
| **对话范式** | `dialogue` | 自由文本；非 ReAct JSON。 |
| **ReAct 范式** | `react` | 结构化 JSON 轮次 + 工具。 |
| **ReAct 步数上限** | `agent.react.max_steps` / `max_QA_steps` | 单轮 ReAct 内 LLM 迭代次数上限；`retrieve_qa` 用 `max_QA_steps` 且按 **每个 user 问题** 计数。 |
| **步数触顶** | `hit_step_limit` / `react_hit_step_limit` | 达上限后 synthesis 收束；GUI 展示说明条，检索问答下再发送则**新开会话**。 |
| **Plan 范式** | `plan` | 先计划再分步（演进中）。 |
| **HITL Plan-and-Execute 范式** | `pipeline` | 人在回路的计划—执行流水线；**非** CI Pipeline。 |

## 3. Skill 与基础设施

| 术语 | 英文 / 代码 | 含义 |
|------|-------------|------|
| **产品 Skill** | `skill_id` | 用户可选的任务配方；≠ MCP Server；≠ Cursor Agent Skills 文件。 |
| **工具 Skill** | Tool Provider | 提供可调用工具（MCP 或 `logos.tools`）。 |
| **基础设施层** | `infrastructure/` | Retrieval、MS、嵌入等全局能力。 |
| **能力层** | `skills/` | MCP 与 manifest。 |
| **持久化档位** | `p0` / `p1` / `p2` | 按「交流强度 × 文件操作强度」划分，与执行范式正交。见下方分类。 |
| **P0 — 流水线型** | `p0` | 低交流 + 高文件操作；粘贴即处理，全自动落盘。当前仅 `import_setting`。 |
| **P1 — 协作创作型** | `p1` | 中交流 + 中文件操作；需与用户讨论、确认后写盘。`setting_write`、`draft_review`。 |
| **P2 — 对话型** | `p2` | 高交流 + 低/无文件操作；产出在聊天消息中完成。`chat_inspire`、`lint_zh`、`retrieve_qa`。 |

## 5. GUI、会话与缓存

| 术语 | 含义 |
|------|------|
| **会话** | **对外首选统称**；档 B 一条 JSON = 一次 Skill 工作单元。 |
| **任务** | 与**会话 1:1 同义**；代码保留 `task_*`、路由 `/task/:id`。 |
| **档 B / 档 C** | 会话缓存 / KSFS 升格轨。 |
| **连续问答** | — | 同一会话内多轮 user 问题（如 `retrieve_qa`）；与「步数续跑」无关。 |

### 5.1 Agent 行动可视（产品边界，2026-05）

**定案：维持现状，不做「推理 + 工具过程」大可视化。**

| 项 | 说明 |
|----|------|
| **主路径（P0/P1）** | 可信与溯源靠 **pipeline 阶段**（`pipeline_step`）、**结果摘要**（路径、`warnings[]`）、**人审**，不靠向普通用户展示 LLM 思考链或 ReAct JSON 全文。 |
| **不立项** | 统一 Agent 时间线、DeepSeek `reasoning_content` SSE、P0 `llm_json` 流式推理展示等。 |
| **保留** | 现有 SSE（含 Lab 下 `react` 的 `reasoning_*` / `tool_trace_*`）、**Pd**（`work` / `developer`）配置；默认 **`work`**，不在任务页扩大推理面板。 |
| **排错** | 与 **展示（Pd）正交**：用 Obs **`maint`** 工具链、`logs/`、聊天 `error` 事件、后端 Traceback；需要细节时用 **范式试验台** + `developer` 档。 |

## 6. 支撑层（Platform layer）

| 术语 | 英文 / 代码 | 含义 |
|------|-------------|------|
| **支撑层** | **PL**；`logos.platform` | `src/logos/platform/`：I&I、S&G、Obs、Config。 |
| **I&I** | `platform/ii_layer/` | HTTP/SSE、组合根装配。 |
| **S&G** | `platform/sg_layer/` | 沙箱、MCP 治理。 |
| **Obs** | `platform/obs/` | 日志；维护轨含 `platform.log` 等。 |
| **端口** | `ports/` | 六边形端口。 |

## 7. 协议与开发工具

| 术语 | 含义 |
|------|------|
| **MCP / SSE** | 见行业通用定义。 |
| **开发用组合根后端** | **Development backend** | 由 `scripts/run_dev_backend.py` 启动的本地 FastAPI（`:8000`）：装配 `AppPorts`、真实或桩 LLM、检索与 MCP。无 API Key 时 LLM 为内存桩（回复前缀「桩后端」）；**不是**与生产对立的「假服务」。 |
