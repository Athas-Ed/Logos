# 架构概览

## 分层模型

Logos 采用自上而下、**端口（ports）隔离实现**的分层结构：

```text
┌─────────────────────────────────────────┐
│  GUI / Electron（任务、设置、缓存页）      │
└──────────────────┬──────────────────────┘
                   │ HTTP + SSE
┌──────────────────▼──────────────────────┐
│  Harness / I&I（api_v1、组合根装配）       │
└──────────────────┬──────────────────────┘
                   │
┌──────────────────▼──────────────────────┐
│  Agent：Shell · CB · PR（范式路由）        │
└──────┬───────────────────────┬──────────┘
       │                       │
┌──────▼──────┐         ┌──────▼──────────────┐
│ Skills(MCP) │         │ Infrastructure      │
│ 可插拔能力   │         │ Retrieval · LLM · … │
└─────────────┘         └──────┬──────────────┘
                               │
                        ┌──────▼──────────────┐
                        │ HDL：KSFS · HSI · SVS│
                        └─────────────────────┘
```

| 层 | 目录（典型） | 职责 |
|----|--------------|------|
| **决策层** | `src/logos/agent/` | 编排任务、拼装上下文、按 Skill 选择范式 |
| **能力层** | `skills/` | MCP 与 manifest 定义的产品 Skill |
| **基础设施** | `src/logos/infrastructure/` | 检索、模型服务等全局能力 |
| **持久层** | `src/logos/persistence/` | KSFS 扫描、HSI/SVS 同步 |
| **支撑层** | `src/logos/harness/` | HTTP、沙箱（S&G）、配置、日志（Obs） |
| **端口** | `src/logos/ports/` | 抽象接口，供 Agent 依赖 |

**Skills 与基础设施分离**：检索、向量库、模型调用属于基础设施；天气、地图等具体能力通过 MCP Skill 按需加载，不默认暴露全量工具给模型。

## 三种「数据地盘」

避免混用以下路径（详见 [KSFS 与叙事知识库](子系统文档/KSFS与叙事知识库.md)）：

| 地盘 | 配置 / 路径 | 角色 |
|------|-------------|------|
| **KSFS** | `paths.ksfs_root`（默认 `resources/ksfs/`） | 已落户的叙事实体，**唯一事实源** |
| **工作区** | `workspace/` | 草稿、`setting_entry/` 等待晋升内容 |
| **索引** | `.index/` | HSI SQLite、Chroma 向量库（可重建） |

## 仓库目录（精选）

```text
Logos/
├── src/logos/          # Python 核心
├── src/gui/            # React 前端
├── src/electron/       # 桌面壳
├── skills/             # Skill manifest 与 MCP 入口
├── config/             # defaults.yaml + 本机 local.yaml
├── resources/          # Prompt、实体模板、示例 KSFS
├── docs/               # 对外介绍文档（本目录）
├── scripts/            # 启动、桩后端等
├── tests/
├── workspace/          # 个人创作（默认不入库）
└── .index/             # 本地索引（默认不入库）
```

`import logos` 的源码根为 `src/logos/`，说明见 [`src/README.md`](../src/README.md)。

## 典型请求路径

1. 用户在 GUI 选择 Skill 并提交输入。
2. 前端 `POST /api/v1/chat`（SSE）携带 `skill_id`、`task_input`、`messages`。
3. Harness 装配端口 → PR 读取 manifest 中的 `paradigm` → Shell 执行对应对话 / ReAct / Pipeline 等。
4. 需要检索时，Infrastructure 经 HSI/SVS 只读 KSFS；结果经 CB 写入上下文。
5. 流式事件返回 GUI；任务状态写入档 B JSON（见 [会话与任务缓存](子系统文档/会话与任务缓存.md)）。
