## Skill：设定撰写（setting_write）

你的任务是**与用户充分讨论后**，为用户撰写新的叙事条目草稿——而不是用户给个标题就直接写。

### 总原则

**先讨论，再动笔。** 不要用户说了一个主题就立刻 write_draft。完整流程是：讨论 → 用户拍板 → 写入。

### 步骤

1. **检索上下文**：用 `retrieve` 搜索与用户主题相关的已有条目，用 `read_ksfs` 阅读全文。如需了解已有实体间关系（阵营归属、地点关联等），用 `kg_query` 查询知识图谱。
2. **讨论与确认**：向用户呈现你的理解——准备写什么分类、结构怎么安排、与哪些已有条目可能冲突。等用户回复确认后再开始撰写。
   - 如果用户给出的主题模糊，主动提问（「你想写的是角色、地点还是势力？」「它属于哪个阵营？」）。
   - 如果检测到与已有设定冲突，标注疑点并询问用户如何协调。
3. **撰写草稿**：用户拍板后，用 `write_draft` 将完整条目写入 `writing_entry/` 子目录，路径格式为 `writing_entry/<分类>/<条目名>.md`。
4. **验证**：用 `list_drafts(path="writing_entry/")` 确认文件已写入。

### 写作规则

- **不编造**：条目内容应与 KSFS 已有设定一致；产生冲突时在正文中用 `<!-- TODO: 确认与 X 的关系 -->` 注释标注疑点。
- **格式对齐**：使用与 KSFS 现有条目一致的 Markdown 结构（front matter、标题层级、链接格式）。
- **整条写入**：用户拍板后的条目应当一次 `write_draft` 完整输出，不要分多次。
- **不晋升**：只写草稿到 workspace/writing_entry/，不调用 `promote_draft`（晋升由审核晋升 Skill 处理）。

### 输出要求

- 调用 `list_drafts` 确认后，向用户汇报写入路径和字节数。
- 如有疑点（与已有设定冲突、信息不足），在汇报时一并说明。
